# ADR 0001：自主、多维数据的交易运行模型

- 状态：Accepted
- 日期：2026-07-26
- 决策者：产品所有者

## 背景

产品需要从大范围股票、ETF 和基金中发现机会，对重点标的进行每日深度分析，并在 Paper 环境中自动执行合格计划。此前“每日研究更新”与“已持仓计划连续性”的关系未被明确，也存在自有数据与 TradingAgents 外部数据各自独立的风险。

## 决策

1. 采用“全市场初筛 → 重点池每日深度研究 → 自动计划/执行 → 持仓持续运营 → 可观察性”的闭环。
2. 不设置逐笔人工批准或 UI 人工风控门槛。系统在 `FINAL_EXECUTABLE` 前使用确定性门槛筛选；最终计划在允许的 Paper 自动交易配置下自动执行。
3. 成交后创建版本化 `PositionPlan`。次日研究可形成新的候选观点，但不得静默替换现有持仓的入场、止损或目标。只有可验证的失效事件可触发自动调整，并必须留下版本和审计记录。
4. 自有数据与 TradingAgents 数据统一到可追溯的 `ResearchSnapshot`。每份数据需要记录来源、时间、质量和降级；TradingAgents 保持研究分析角色，Runtime 保持唯一订单执行角色。
5. NiceGUI 和 Discord 用于解释、审计和简报，不拥有下单权限。

## 后果

- 需要新增统一研究快照、持仓计划生命周期和失效事件的显式契约与持久化迁移。
- TradingAgents 的外部数据调用需要逐步纳入来源治理，不能作为不透明的第二套生产事实。
- 自动化不代表绕过现有安全边界：仅 Paper、限价单、风险、Kill Switch、幂等性、订单持久化与重启恢复仍为强制条件。
- 本 ADR 定义目标架构，不表示这些待实现能力已经上线；当前生产基线以 `AGENTS.md` 为准。
