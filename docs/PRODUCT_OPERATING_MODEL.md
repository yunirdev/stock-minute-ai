# 产品运行模型

状态：目标定义（2026-07-26）  
适用范围：Alpaca Paper Trading；不授权自动实盘交易。

## 产品目的

系统的目标是在完整、可追溯、多维的数据基础上，自动寻找并执行风险受控的盈利机会。NiceGUI 和 Discord 负责透明展示与通知；它们不是逐笔审批入口。Runtime 是唯一能提交订单的生产组件。

当前交付小目标是让 AI 在现有 Alpaca Paper 环境连续完成“数据获取 →
市场分析 → 交易计划 → 执行 → 风险控制 → 复盘反思 → 策略候选迭代”的
闭环，并让全部 NiceGUI 按钮产生完整、可解释、可回放、可量化的结果。
详细验收以 [CLOSED_LOOP_ACCEPTANCE.md](CLOSED_LOOP_ACCEPTANCE.md) 为准。

## 五段运行闭环

1. **全市场初筛**：从股票、ETF 和基金的可交易范围中，使用流动性、可交易性、市场状态、策略证据与风险条件选出重点关注池。
2. **重点标的深度研究**：每天为关注池生成完整研究快照。自有数据和 TradingAgents 补充数据都进入同一份、有时间边界和来源记录的研究输入。
3. **自动形成并执行交易计划**：系统只让通过策略、研究证据、仓位、风险和执行条件的计划进入 `FINAL_EXECUTABLE`。进入该状态即自动批准：在 `--auto-trade` 且 Paper 配置有效时，Runtime 自动提交限价单；否则记录为 `DRY_RUN`。
4. **持仓持续运营**：成交后建立持久化的持仓计划，而不是每天把原计划静默改写。系统持续监控风险、行情、订单和经验证的失效事件，必要时自动减仓、退出或收紧止损。
5. **可观察性**：NiceGUI 展示数据来源、研究结论、计划版本、订单、持仓与失效原因；Discord 仅发送简报（启用发送前仍需产品层面的外部发送授权）。

## 自动化与计划连续性

不设逐笔人工确认，也不以 UI 人工风控作为交易门槛。系统门槛发生在计划成为最终计划之前；最终计划由系统自动执行。

交易对象必须区分为：

- `CandidatePlan`：候选研究结论，可以每日更新，不能下单。
- `FinalTradePlan`：已通过确定性门槛的执行计划，可自动下单。
- `PositionPlan`：首次成交时冻结的持仓基线和版本链。原始入场依据、初始止损和目标必须可追溯。
- `InvalidationEvent`：有可信来源、明确生效时间和确定性规则的事实变化，例如止损触发、公司行动、交易限制或已验证的策略失效。
- `PositionAdjustment`：由失效事件驱动的自动减仓、退出、止损收紧或其他可审计调整；不得把“次日重新研究”直接当作静默改写已持仓点位的理由。

对于多头，止损默认只能收紧而不能放宽；任何目标或仓位变化都必须产生新版本和原因记录。重启后必须能从持久化记录恢复这些约束。

## 统一研究数据原则

每次研究应建立一个 `ResearchSnapshot`：包含数据值、来源、抓取时间、数据截止时间、覆盖范围、质量状态和失败信息。模型或规则只能基于该快照形成结论，不能把来源不明的实时数据悄悄混入结论。

目标数据维度包括：

- 行情、成交量、公司行为与账户/订单事实：Alpaca 为执行与行情主源。
- 财务、公告、内幕与监管披露：SEC EDGAR 等一手来源。
- 新闻、事件、宏观和日历：Finnhub、WallStreetCN、Nasdaq、FRED 等。
- 补充研究覆盖：Yahoo Finance、TradingAgents 的技术/基本面/新闻数据、StockTwits、Reddit、Polymarket。
- 系统自身事实：本地历史缓存、策略统计、历史成交、滑点、持仓和审计记录。

来源之间不是“二选一”。它们应在统一快照中按领域优先级、时间新鲜度和质量状态协调；冲突、缺失和降级必须可见。

## 当前边界

当前生产路径已经具备每日研究、冻结研究快照、PaperDecision、ATR 计划、确定性风险、Alpaca Paper 限价执行、订单轮询、审计及 NiceGUI 监控。统一数据快照、持仓计划版本链、失效事件契约和全市场数据治理是目标架构，必须通过独立实现任务逐步落地，不能仅因本文档而视为已上线。

复盘建议不得直接修改生产策略。策略迭代必须形成新版本，经独立
holdout、历史回放、Paper 对照和回滚验证后才能晋升。
