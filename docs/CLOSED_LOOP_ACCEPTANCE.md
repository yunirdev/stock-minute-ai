# AI 交易闭环交付验收

状态：当前小目标  
适用范围：当前配置的 Alpaca Paper 环境；不授权自动实盘交易。

## 交付目标

AI 必须能够连续、独立完成：

```text
数据获取
  → 市场分析
  → 制定交易计划
  → Paper 执行
  → 风险控制与持仓调整
  → 成交后复盘反思
  → 产生可验证的策略候选版本
  → 下一轮数据与研究
```

最终计划不需要逐笔人工批准。Runtime 仍是唯一订单提交者；自动执行仍限
Alpaca Paper 和 LMT。复盘可以产生策略候选版本，但未经独立 holdout、
回放和 Paper 对照验证，不得静默替换当前生产策略。

## 闭环完成定义

一次端到端闭环必须产生稳定 ID 和版本引用，并能从最终结果反向追溯：

| 阶段 | 必须产生的证据 | 当前主要任务 |
| --- | --- | --- |
| 数据获取 | `ResearchSnapshot`、source manifest、as-of、质量与失败 | B、C |
| 市场分析 | research run、模型/提示词/数据版本、结构化结论 | D |
| 交易计划 | Candidate/Final/Position plan、价格、目标、止损、失效条件 | E、F |
| 交易执行 | OrderIntent、broker order、fill、幂等键、对账状态 | A、F |
| 风险控制 | 计划风险、累计仓位、Kill Switch、调整原因和结果 | A、E |
| 复盘反思 | 计划与实际成交、滑点、收益、风险事件、错误归因 | F04–F05 |
| 策略迭代 | 不可变候选版本、训练/holdout 边界、对照指标、回滚信息 | F06–F07 |
| 用户解释 | 任一订单的完整调用链、版本链和量化指标 | H |

确定性步骤必须可重复计算并得到相同结果。LLM 输出不要求重新生成相同
文字；系统必须冻结原始输入和输出，并用冻结输出重放后续确定性决策。

## 量化验收

闭环报告至少包含：

- 数据覆盖率、失败率、新鲜度、来源冲突和降级次数。
- TradingAgents 成功率、耗时、模型版本、结构化输出合格率。
- 候选计划数、最终计划数及每个拒绝原因的数量。
- 下单成功率、成交率、部分成交、滑点、UNKNOWN 和重试/防重统计。
- 单笔风险、累计仓位、最大回撤、Kill Switch 和调整事件。
- 计划收益与实际收益、胜率、盈亏比、风险调整后收益和基准差异。
- 策略候选相对当前版本的 holdout 指标、Paper 对照结果和回滚条件。

报告不以“盈利”作为伪造的通过条件；它验证系统能准确记录收益和风险，
并证明策略升级基于样本外证据，而不是根据单次盈亏自我修改。

## 加速验收

自然观察不阻塞代码迁移：

1. 历史回放验证数据、规则、计划、风险、复盘和策略指标的正确性。
2. 隔离 Paper 场景验证 BUY/SELL/拒绝/部分成交/UNKNOWN/重启和故障恢复。
3. 当前配置运行短期真实 Paper 影子/闭环采样，验证网络延迟和外部状态。
4. 长期自然 Paper 观察作为成熟度验收继续积累，不伪装成历史回放。

历史证据、隔离演练和真实运行证据必须分表、分报告显示。

## NiceGUI 按钮验收

当前源码渲染 17 个按钮动作。权益曲线跨度（原 6 个按钮）和 Discord 报告类型
（原 4 个按钮）已收敛为"下拉选择 + 单一执行按钮"，能力不变、按钮数量减少；
新增"发送个股分析"手动推送。H01/H05 建立的机器可检查动作契约随之更新，
继续逐项验证成功、空数据、错误和重复点击状态。

| 页面/区域 | 按钮动作 |
| --- | --- |
| 总览 | 刷新市场环境、运行今日研究、切换权益曲线跨度（下拉） |
| 系统 | 启动引擎、停止引擎 |
| Discord | 发送 Discord 简报（下拉选报告类型：晨报/盘中 OR-VWAP/每日复盘/方向复盘）、发送个股分析（手动，任意标的） |
| 因子分析 | 运行分析 |
| 回测 | 运行回测 |
| 标的池 | 全部重建、全市场扫描、更新长期池、更新决策池、清除筛选 |
| 风控 | 触发急停、解除急停 |
| 维护 | 运行维护分析 |

每个按钮必须满足：

1. 有唯一 handler，不因重绘重复绑定。
2. 长任务不阻塞 UI，并在运行时禁止重复触发或幂等处理。
3. 成功时输出完整结果或明确的持久记录引用。
4. 空数据不是假成功，必须显示缺少什么以及如何恢复。
5. 失败必须显示去敏错误并恢复按钮状态。
6. 外部发送、引擎启停和 Kill Switch 等重要动作必须留下审计证据。
7. UI 关闭不影响 Runtime；UI 不成为逐笔审批或第二订单入口。
